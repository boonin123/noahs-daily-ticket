# Daily Ticket — Implementation Plan

A morning desktop summary image generated by `launchd` at 8:00 AM Mac local time. Pulls weather (geolocated via IP), important Gmail emails (ranked by Claude), and sports updates for five teams, then renders a clean-serif journal-style PNG and overwrites `~/Desktop/daily-ticket.png`.

**Stack:** Python 3.11+, `requests`, `Pillow`, Gmail Python SDK, `anthropic`, macOS `launchd`.
**Project root:** `~/Desktop/projects/daily-ticket/`
**Owner:** noah@boonin.net

## Phase 0 — Documentation Discovery (reference, complete)

This section is the verified API surface. All other phases reference it. **Do not invent endpoints or method names beyond what's listed here** — if something's missing, re-verify before adding.

### Allowed APIs

#### Gmail (Python SDK)
- **Packages:** `google-api-python-client`, `google-auth-httplib2`, `google-auth-oauthlib`
- **Scope:** `https://www.googleapis.com/auth/gmail.readonly`
- **OAuth pattern:** `InstalledAppFlow.from_client_secrets_file("credentials.json", SCOPES).run_local_server(port=0)` → save to `token.json` → reload with `Credentials.from_authorized_user_file` and refresh via `creds.refresh(Request())` when expired.
- **List call:** `service.users().messages().list(userId="me", q="newer_than:1d", maxResults=50).execute()` — returns IDs only.
- **Get call:** `service.users().messages().get(userId="me", id=msg_id, format="metadata", metadataHeaders=["From","Subject"]).execute()` — cheaper than `format="full"`.
- **JSON paths:** sender/subject in `payload.headers[]` array (match by `name`); `snippet` at top level; `labelIds[]` contains `"UNREAD"` and/or `"IMPORTANT"`.
- **Anti-patterns:** Don't use `format="full"` for header-only needs. Don't request `gmail.modify` scope.

#### Open-Meteo weather
- **Endpoint:** `https://api.open-meteo.com/v1/forecast` (no API key).
- **Params:** `latitude`, `longitude`, `current=temperature_2m,weather_code`, `daily=temperature_2m_max,temperature_2m_min,precipitation_probability_max`, `temperature_unit=fahrenheit`, `timezone=auto`.
- **Response paths:** `current.temperature_2m`, `current.weather_code`, `daily.temperature_2m_max[0]`, `daily.temperature_2m_min[0]`, `daily.precipitation_probability_max[0]`.
- **WMO weather codes:** 0 clear; 1–3 mainly clear → overcast; 45/48 fog; 51–67 drizzle/rain/freezing rain; 71–86 snow; 95–99 thunder.
- **Anti-pattern:** the canonical param name is `weather_code` (snake_case), not `weathercode`.

#### ip-api.com geolocation
- **Endpoint:** `http://ip-api.com/json/` (HTTP only on free tier — do **not** force HTTPS).
- **No key.** Rate limit 45 req/min.
- **Response fields:** `lat`, `lon`, `city`, `regionName`, `country`, `status` (`"success"` / `"fail"`).

#### ESPN public sports API
- **Base:** `https://site.api.espn.com/apis/site/v2/sports`
- **Date filter:** `?dates=YYYYMMDD` on the scoreboard endpoint (verified MLB; pattern attested across leagues).
- **Scoreboard JSON paths:** `events[i].competitions[0].competitors[j].score`, `…homeAway`, `…team.displayName`, `events[i].competitions[0].status.type.state` (`pre`/`in`/`post`), `events[i].competitions[0].date`.
- **News JSON paths:** `articles[i].headline`, `articles[i].description`, `articles[i].published`.

| Team | League slug | Team ID |
|---|---|---|
| NY Giants (NFL) | `football/nfl` | `19` |
| SF Giants (MLB) | `baseball/mlb` | `26` |
| Chelsea FC (EPL) | `soccer/eng.1` | `363` |
| Cal Football (NCAA FBS) | `football/college-football` | `25` (use `?groups=80` for FBS filter) |
| Golden State Warriors (NBA) | `basketball/nba` | `9` |

- Per-team endpoints: `/{league}/scoreboard?dates=…`, `/{league}/teams/{id}/schedule`, `/{league}/news?team={id}`.
- **Caution:** Use numeric team IDs in URLs, not slugs (Chelsea slug returned HTTP 400 in testing).

#### Anthropic SDK
- **Package:** `anthropic`
- **Model for email ranking:** `claude-haiku-4-5-20251001` (cheap, fast, plenty smart for this task).
- **Use prompt caching** on the system prompt (the rubric for "important") since it's identical every day.

## Phase 2 — Data fetchers (no LLM)

**Goal:** Four standalone fetcher modules, each runnable from CLI for smoke testing, returning plain Python dicts.

### What to do

Create four files under `fetchers/`. Each should have a `fetch()` function returning a dict, plus an `if __name__ == "__main__": print(json.dumps(fetch(), indent=2))` block for manual testing.

1. **`fetchers/geo.py`** — calls `http://ip-api.com/json/`, returns `{"lat", "lon", "city", "region", "country"}`. Copy the snippet in Phase 0 → ip-api section.

2. **`fetchers/weather.py`** — takes `(lat, lon)`, calls Open-Meteo per the Phase 0 params, returns `{"temp_now", "code", "condition", "high", "low", "pop"}` (condition = mapped human string from WMO code). Include the WMO code→string mapping inline (Phase 0 lists the ranges).

3. **`fetchers/sports.py`** — exports `fetch_all_teams()` returning a list of dicts, one per team, with keys `{"team", "status", "last_game", "next_game", "headline"}`. Status is one of `"recent"`, `"upcoming"`, `"offseason"`. For each team:
   - Compute yesterday's and today's `YYYYMMDD`.
   - Hit `{base}/{league}/scoreboard?dates=YYYYMMDD` for both days; iterate `events[].competitions[0].competitors[]` and match `team.id == "<TEAM_ID>"`.
   - If a finished game is found for yesterday → fill `last_game`.
   - If a scheduled game is found for today → fill `next_game`.
   - If neither → hit `/{league}/news?team={id}`, take `articles[0].headline` → fill `headline`, set status to `"offseason"`.
   - Use the team table from Phase 0. **Use numeric team IDs only.**
   - For Cal football, add `&groups=80` to scoreboard requests.

4. **`fetchers/gmail.py`** — `fetch_recent_emails()` calls Phase 0's list + get pattern, returns a list of dicts: `[{"sender", "subject", "snippet", "unread", "important"}, ...]`. Limit to ~30 messages from the last 24h. Read `token.json` and `credentials.json` from `Path.home() / "Desktop" / "projects" / "daily-ticket"`.

### Documentation references
- Phase 0 — copy-ready snippet blocks. **Do not deviate from the param names or JSON paths listed there.**

### Verification checklist
- [ ] `python -m fetchers.geo` prints a city + lat/lon.
- [ ] `python -m fetchers.weather` (after passing in geo) prints a temp and a condition string.
- [ ] `python -m fetchers.sports` prints 5 team blocks, each with a status field set to one of the three allowed values.
- [ ] `python -m fetchers.gmail` prints a list with non-empty sender/subject on at least one entry.

### Anti-pattern guards

## Phase 4 — Rendering the ticket

**Goal:** A function `render_ticket(weather, emails, sports) -> Path` that writes `~/Desktop/daily-ticket.png` and returns its path.

### What to do

Create `render.py`. Layout decisions:

- **Canvas:** 1200×1600 px, white background. Clean serif throughout.
- **Font:** Georgia at `/System/Library/Fonts/Supplemental/Georgia.ttf` (pre-installed on macOS — verify with `ls` first). Fallback: `/Library/Fonts/Georgia.ttf` if older macOS. If neither path exists, halt the phase and pick a different system serif.
- **Sizes:** title 56pt, section headers 32pt, body 22pt, footer 16pt.
- **Margins:** 80px all sides. Sections separated by a thin 1px horizontal rule with 40px vertical padding above and below.

Section structure (top to bottom):

1. **Header:** "Monday · May 11, 2026" centered (use `datetime.now().strftime("%A · %B %-d, %Y")`).
2. **Weather:** "Boston, MA · 58° now, cloudy → 67°/52°, 10% rain" — one line.
3. **Inbox:** section header "Inbox", then up to 5 bullet lines: `• {sender_short} — {summary}`. If empty: "Nothing pressing."
4. **Sports:** section header "Sports", then one line per team:
   - `recent`: `SF Giants    L 3–5 vs LAD · today vs SD 9:45 PM`
   - `upcoming`: `Warriors     tonight vs MIN 10:30 PM`
   - `offseason`: `Chelsea      offseason · Palmer extension talks ongoing`
   - Use fixed-width team-name column (~14 chars left-padded with spaces) so values line up.

Helper functions to write inline (don't over-engineer):
- `_text_lines(draw, text, font, x, y, max_width)` to handle wrapping for any long bullet.
- `_rule(draw, y)` for the dividers.

### Documentation references
- Pillow docs: `ImageDraw.Draw.text()`, `ImageFont.truetype()`. These APIs are stable; no need to re-verify.
- Phase 0 → no rendering-specific findings; this phase is internal logic only.

### Verification checklist
- [ ] `python render.py` with mock data produces `~/Desktop/daily-ticket.png` at 1200×1600.
- [ ] File opens in Preview and looks like the journal layout — date at top, three sections, dividers between them.
- [ ] Long bullets wrap inside the canvas rather than overflowing the right margin.
- [ ] Empty inbox renders "Nothing pressing." rather than an empty section.

### Anti-pattern guards
- Do **not** download a custom font in this phase — Georgia is on macOS by default. Custom fonts are a Phase 5+ improvement if you want them.
- Do **not** try to draw the image with `matplotlib` — Pillow gives crisper text for this kind of layout and matches the journal aesthetic better.

## Phase 5 — Orchestration + launchd

**Goal:** A single `main.py` that runs all fetchers, calls the ranker and renderer, and writes the file. Then a `launchd` plist that fires it daily at 8:00 AM.

### What to do

1. **`main.py`:**
   ```
   load .env → fetch geo → fetch weather(lat, lon) → fetch sports → fetch gmail → rank emails → render → log success
   ```
   - Wrap each step in try/except; on failure, log to `logs/run.log` (use `logging.FileHandler`) and continue with `None` for that section. Renderer must handle `None`/empty sections gracefully (Phase 4 already covers empty inbox; extend to weather and sports).
   - Last line: log `Wrote ~/Desktop/daily-ticket.png at HH:MM:SS`.

2. **launchd plist** at `~/Library/LaunchAgents/net.boonin.daily-ticket.plist`:
   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
   <plist version="1.0">
   <dict>
     <key>Label</key>            <string>net.boonin.daily-ticket</string>
     <key>ProgramArguments</key>
     <array>
       <string>/Users/noahboonin/Desktop/projects/daily-ticket/.venv/bin/python</string>
       <string>/Users/noahboonin/Desktop/projects/daily-ticket/main.py</string>
     </array>
     <key>WorkingDirectory</key> <string>/Users/noahboonin/Desktop/projects/daily-ticket</string>
     <key>StartCalendarInterval</key>
     <dict>
       <key>Hour</key>   <integer>8</integer>
       <key>Minute</key> <integer>0</integer>
     </dict>
     <key>StandardOutPath</key>  <string>/Users/noahboonin/Library/Logs/daily-ticket/stdout.log</string>
     <key>StandardErrorPath</key><string>/Users/noahboonin/Library/Logs/daily-ticket/stderr.log</string>
     <!-- Keep stdio off ~/Desktop: macOS TCC blocks launchd/xpcproxy from
          opening files in the Desktop folder, which causes EX_CONFIG (78)
          and the job never spawns. -->

   </dict>
   </plist>
   ```

3. Load it: `launchctl unload ~/Library/LaunchAgents/net.boonin.daily-ticket.plist 2>/dev/null; launchctl load ~/Library/LaunchAgents/net.boonin.daily-ticket.plist`.

4. **Force-run for verification** without waiting until 8 AM: `launchctl start net.boonin.daily-ticket`.

### Documentation references
- Apple's `launchd.plist(5)` man page (`man launchd.plist`) — `StartCalendarInterval` keys are stable across macOS versions.
- No external docs needed beyond Phase 0's APIs.

### Verification checklist
- [ ] `~/Desktop/projects/daily-ticket/.venv/bin/python ~/Desktop/projects/daily-ticket/main.py` runs end-to-end with no traceback; writes a fresh image to the Desktop.
- [ ] `launchctl list | grep daily-ticket` shows the job loaded.
- [ ] `launchctl start net.boonin.daily-ticket` triggers a run and updates the Desktop image; check `~/Library/Logs/daily-ticket/stdout.log` and `stderr.log` for output.

### Anti-pattern guards
- Do **not** use `cron` instead of launchd — cron on macOS doesn't survive sleep/wake cleanly and won't fire if the Mac was asleep at 8 AM. launchd will catch up on next wake.
- Do **not** put environment variables in the plist; load them via `python-dotenv` inside `main.py` so they're managed in one place.
- Do **not** assume the network is up — fetchers should already tolerate failures from Phase 2. If they don't, fix that, don't add a sleep/retry in main.
- Do **not** use absolute paths copy-pasted from this plan if you're a different user — the plist must be regenerated with the correct home dir.
